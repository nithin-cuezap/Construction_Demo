# Project Instructions

Use scoped instruction files for domain-specific behavior:

- For coding standards, SOLID principles, and documentation, follow [coding-standards.instructions.md](coding-standards.instructions.md).
- For data persistence and state updates, follow [mockdb.instructions.md](mockdb.instructions.md).
- For UI design, styling, and theme consistency, follow [design-theme.instructions.md](design-theme.instructions.md).
- When executing commands in commandline, make sure terminal is in {project-root}/Construction-demo directory.
- When making code changes, include tsdoc style comments for all functions, classes, and complex logic to ensure maintainability and clarity for future developers. Do not explain what changed, but rather what the code does and why it does it that way.

Conflict handling:

- Prefer the more specific scoped instruction over this global file.
- If two scoped rules conflict, prefer the one with tighter file targeting.
